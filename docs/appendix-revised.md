## 附录，把统一训练落成一份能搬进训练栈的实现

正文的结论来自论文。这一附录只做一件事，把算法本身写成一份短而可读的代码，方便你对照自己的训练栈，判断哪些部分值得接进专业模型的训练。代码用的是 80 万参数的玩具模型，能在 CPU 上跑通，但它的数值没有参考意义，所以这里不报效果，只讲实现，并说明实现本身怎样被验证。

**源码仓库**为 https://github.com/weiping/single-algorithm-toy ，包含全部代码、两份配置和验证记录。下文的命令都在仓库根目录执行，环境为 Python 3 加 PyTorch 2.15.0。

### 一份实现要对上的七件事

**一，样本是 (z, w)。** 每个 token 带一个权重，提示部分为 0，预训练和中训为 1，RL 的回答部分为奖励权重（`unified.py` 里的 `Example`）。多数训练栈已经有 loss mask，把它从 0/1 放宽成浮点权重就够了。

**二，一个损失，分母是批内非提示 token 的总数。** 对应 `weighted_loss`。有两处容易出错。权重为零的回答，它的 token 也要算进分母。分布式训练时，分母要在所有卡上汇总之后再除，否则每张卡各除各的，等于悄悄改了权重。后一点论文没有讨论，是我从实现角度做的推论，需要在自己的栈里验证。

**三，RL 的权重只有一行。** 对应 `rl_weights`。一道题采样 N 条，正确回答权重取 N/k（k 为答对条数，即 1/p̂），错误回答为 0，全错的题整体记零。换成 REINFORCE 只要把 N/k 改成 1。权重只由本组的通过率决定，不依赖另一个价值模型。这意味着现有的验证器和采样服务可以原样复用，只替换权重的计算。

**四，混合按 token 占比，速率正比于 f_s/T_s。** 对应 `MixtureSampler` 和 `draw_mixed_batch`。T_s 取损失 token 的平均数，不含提示。上线前像 `check.py` 那样抽样自检一遍，看实测占比与目标占比是否对得上。

**五，配比是一条曲线。** 对应 `pipeline.py` 和 `configs/`。每个数据源有一条随优化步变化的占比曲线，学习率也是一条曲线，同一份训练代码读取它们。

**六，生成与训练解耦。** 生成器用一份落后的权重副本，每隔几次更新同步一次，并记录策略滞后（`rl_phase` 与 `pipeline.py`）。论文的异步系统里实测滞后在 12 到 44 次更新之间。这里是单进程模拟，只能验证逻辑，吞吐上的收益要在自己的系统里测。

**七，用最终表现选检查点。** 保留每个阶段的检查点，放到同一套下游任务上评测，同时评测一份真正留出的前序语料。`task.py` 里有按哈希切分的做法，保证留出集从未进入训练。

### 配比轨迹的两份配置

分阶段训练和统一训练用的是同一份训练代码，差别只在配置。横坐标相同的两个点表示跳变。

分阶段，占比只取 0 或 1，在阶段边界跳变。

```json
"web": {"kind": "lm",  "weight": [[0, 1], [400, 1], [400, 0]]},
"mid": {"kind": "sft", "weight": [[0, 0], [400, 0], [400, 1], [600, 1], [600, 0]]}
```

统一，占比连续变化，来源长期重叠，RL 期间继续混入 15% 的中训数据。

```json
"web": {"kind": "lm",  "weight": [[0, 1], [200, 1], [200, 0.5], [400, 0.5], [400, 0]]},
"mid": {"kind": "sft", "weight": [[0, 0], [200, 0], [200, 0.5], [400, 0.5], [400, 0.15], [550, 0.15], [550, 0]]}
```

有 RL 来源的步骤，先用生成器做一批 rollout，以它的损失 token 数为基准，再把其余来源补到各自占比对应的 token 数。这一段只有十几行，在 `pipeline.py` 的 `run` 里。

### 搬进专业训练栈的顺序

下面按改动成本从低到高排列。前三步有论文的实验支持，后两步是我的建议，需要自己做对照。

**第一步，改评测与检查点选择。** 不需要重新训练。论文的持续学习实验说明，阶段内指标领先的检查点，不一定对后续学习最有用。

**第二步，在现有 RL 阶段混入 0.5% 到 5% 的前序数据。** 一定要设零混合对照，同时评测主任务、没有训练的任务和留出语料。论文这一组实验用的是 0.76B 模型和数学 RL，更大规模上是否成立没有证据。

**第三步，把阶段边界改成配置里的曲线。** 试一试半程退火。论文里混入的时机是一个独立的变量，调度不同，代码任务和留出损失的取舍也不同。

**第四步，把 RL 权重换成 MaxRL，并与现有做法对照。** 论文里 MaxRL 的覆盖率更高，REINFORCE 的准确率和保留性更好，两者在这份代码里一个开关就能切换。

**第五步，最后才动统一训练器和异步生成。** 这一步改动最大，主要工作量在数据管线、检查点逻辑和调度系统里的阶段假设。

每一步的对照协议都一样，同一个初始化、同一条数据流、同样的算力，多个种子。

### 验证

实现分两层验证，记录在仓库的 `docs/verification.md` 里。

**模块级，`check.py`，七条，几秒跑完。** 它们验证成功条件分布的恒等式，有限 N 时期望梯度恰好等于 [1−(1−p)^N]·∇log p（对全部采样结果精确枚举），每题权重之和固定为 N，全错回答仍计入分母，混合采样的实测 token 占比，数据切分与评测去重，以及配比曲线的跳变和归一化。七条全部通过。

**运行级，`verify.py`。** 让分阶段与统一两份配置各完整走一遍，把每一步的运行记录与算法约定逐项核对。步数缩放为 0.25，种子 0，两份配置各 6 项，全部通过。

- 实测 token 占比与曲线目标一致。统一配置的最大偏差为 0.0100，例如中训目标 0.50 实测 0.490，RL 期间中训目标 0.15 实测 0.152，RL 目标 0.85 实测 0.848。分阶段配置的偏差为 0。
- 分阶段配置 212 步中，每一步的数据都只来自一个来源。统一配置 162 步中有 88 步多个来源混合。
- RL 每道题的权重之和，1488 道题里没有一道违反只能是 0 或 N 的约定，其中全错的有 790 道（分阶段）和 728 道（统一）。
- RL 提示流共抽取 1488 道题，与评测题的重叠为 0。
- 策略滞后的均值，理论值 1.468，实测 1.468。
- 预训练阶段的训练损失，首段均值 11.7，末段分别降到 1.46 和 1.31。

RL(A) 训练通过率首尾对比只是观察项，不判定。首四分之一与末四分之一的均值，分阶段为 0.087 与 0.117，统一为 0.067 与 0.096，方向向上，但运行很短，不构成结论。

没有验证的内容也要说清。没有比较统一与分阶段的效果，也没有与论文数值对照。异步是单进程里用落后的权重副本模拟的，真实系统的吞吐和陈旧度没有验证。分布式下分母跨卡汇总没有验证。

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python check.py
.venv/bin/python verify.py --steps-scale 0.25
.venv/bin/python pipeline.py --config configs/staged.json
.venv/bin/python pipeline.py --config configs/unified.json
.venv/bin/python train.py --seeds 0 1 2
```

`verify.py` 在单核 CPU 上约三分钟。`train.py` 是三种练法的并排对照，带零混合对照，耗时更长，不属于验证的内容。

### 局限

模型只有 80 万参数。异步是单进程模拟。论文本身的证据也只到 1.24 亿和 0.76B 参数。所以这份实现能告诉你机制怎么写，但没法告诉你在专业模型上收益有多大，这需要按上面的顺序自己做对照。
