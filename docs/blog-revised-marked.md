## 为什么训练一个大模型，要把算法换四次

一个大模型从一张白纸走到会解题，通常要过四道工序。

先是预训练（pretraining），喂给它海量文本，让它学会语言和世界的大致样子。

然后是中训（midtraining），用精选语料补上数学、代码和推理这类专门内容。

接着是监督微调（Supervised Fine-Tuning，SFT），拿人写的示范教它按指令作答。

最后是强化学习（Reinforcement Learning，RL），让模型自己生成答案，答对有奖励，答错没有，靠这个信号把能力磨尖。

四道工序各有一套数据、一个损失函数、一组超参数和一份训练代码。上一道结束，下一道换整套东西重新开始。

这个做法写进了几乎所有主流训练配方，研究也随之分了家。

预训练有预训练的规模定律（scaling law），强化学习有强化学习的，工序之间怎样互相干扰、互相迁移，又是第三批文献在谈。

分工越细，一个很朴素的问题越没人被逼着回答。

这四道工序之间的界线，是训练本身要求的，还是流程一路沿用下来的习惯？

~~答案很明确：界线可以拿掉。~~<u>论文的回答是，界线在算法上可以拿掉。</u>预训练、中训、微调和强化学习，能写成同一个训练算法<u>（限于上文说的几类强化学习目标）</u>，区别只留在喂什么数据、各占多大比例、什么时候喂。

他们的实验里有一个结果，很难用旧流程来解释。

同一个数学模型接着去训代码，起点时代码准确率更低的那一批，到终点反而更高。<u>这组实验用的是 0.76B 的模型，后文会细说。</u>

要看懂这件事，得先弄清两个问题。强化学习怎么才能跟预训练用同一个损失，一个训练系统又怎样把四道工序装进同一个循环。

弄清之后，再看实验里准确率、覆盖率和遗忘怎样互相牵扯，你会得到一个看训练的新角度，把一次训练看成一条随时间变化的数据配比曲线。

## 把做对的答案，当成语料来训练

先从最熟悉的部分讲起。预训练、中训和监督微调做的是同一件事。

给模型一段文本，问它按现在的参数把这段话写出来的可能性有多大，再调整参数，让这个可能性变大。这叫最大似然估计（Maximum Likelihood Estimation，MLE）。

预训练拿网页当文本，中训拿精选语料，微调拿指令加示范，换掉的只是文本，损失函数一个字都没变。

强化学习看上去是另一个物种。

它的目标是让期望奖励最大，答案由模型自己生成，由程序打分，手边没有一份固定的文本可以拿来拟合。梯度的形式不同，优化目标不同，这就是四道工序一直分着走的数学原因。

要拆开这道障碍，得从一个干净的设定开始，奖励只有对和错两种。对某道题，模型答对的概率记作 p。

再设想一个只含正确答案的分布，也就是把模型所有回答里答错的都拿掉，剩下的按原有概率重新归一。这个分布叫成功条件分布。

整套思路从下面这个等式出发。要让 p 的对数变大，梯度恰好等于在成功条件分布上做最大似然的梯度。

$$\nabla_\theta \log p_\theta(x) = \mathbb{E}_{y\sim\pi_\theta^{+}(\cdot|x)}\left[\nabla_\theta \log\pi_\theta(y|x)\right]$$

用话来说，强化学习的每一步更新，都是在模仿模型自己当前所有答对的回答。

再往前走一步，只要在一次更新里把这批正确答案固定住，它就成了一份语料，这一步的损失与预训练的损失，写出来是同一个式子。

强化学习从此只是多了一种数据来源，学习方式和预训练相同。

现实里没法穷举所有答案，只能每道题采样 N 条，再估计通过率。接下来是权重的设计。

答对的回答，权重取通过率的倒数，答错的回答权重为零。~~取倒数的理由是，越难的题，答对一条越稀有，值得更大的权重去学。~~<u>取倒数是为了让一道题所有正确回答的权重加起来保持固定。比如一道题采样 4 条，答对 2 条，每条正确回答的权重是 2，答对 1 条，这一条的权重是 4。每道题的总权重相同，所以 MaxRL 保留原来的题目分布。题目被降权只出现在采样条数 N 有限的时候，很少被解出的题可能一条正确回答也采不到。</u>

全答错的题没有可模仿的对象，所有权重归零，对梯度没有贡献。通过率为零时倒数没有定义，实现时要事先约定这一组整体记零。<u>这些全错回答的 token 仍然计入损失的分母（论文附录 C.3），复现时最容易漏掉这一点。</u>

N 取 1 时，这个估计退化成经典的 REINFORCE（一种策略梯度算法），N 越大，越接近精确的最大似然。

这条思路的前身叫 MaxRL（Maximum Likelihood Reinforcement Learning，最大似然强化学习），统一训练在它的基础上把静态数据和强化学习生成的数据放进同一个公式。

这个改写带来两个后果。

~~模仿的对象由谁生成并不重要，~~<u>模仿的对象可以由别的策略生成，</u>只要生成者在构造这批数据时保持不动，它的成功回答同样是一份合法的~~语料~~<u>似然目标。此时拟合的是那个生成者的成功分布，一般不再等于当前模型自己的 MaxRL 梯度（论文第 3.2 节）。</u>所以生成和训练可以拆开~~，让更强的模型去生成，训练一个更小的模型~~。<u>论文没有测过让更强的模型生成、再去训练更小模型的用法。</u>

另一个后果是，各种强化学习算法之间的差别也被摊开了。MaxRL 保留原来的题目分布，REINFORCE 把更大的权重给通过率高的题，连续奖励的变体，以及只取奖励分布尾部的 TailRL，也都能放进同一张表。

选强化学习算法，于是拆成两个能分别回答的问题，模仿谁，以及哪些题多练。

## 一张权重表，装下整个训练史

损失统一以后，数据格式也能统一。

每个训练样本是一段 token（词元）序列，外加一个与 token 一一对应的权重向量。预训练和中训的每个 token 权重都是 1。

监督微调里，提示部分的权重为 0，示范部分为 1，因为模型只需要学怎么回答，不需要学怎么提问。强化学习沿用同样的提示掩码，回答部分乘上刚才算出的权重。

在 trainer（训练器）眼里，没有预训练和强化学习之分，只有权重不同的序列，一个加权似然损失处理所有来源。

<u>论文里的损失（式 2）取批内的 token 均值，写出来是下面这样。其中 T_B 是批内非提示 token 的总数，权重为零的全错回答也算在里面。</u>

<u>$$\hat L(\theta; B) = -\frac{1}{T_B}\sum_{(z,w)\in B}\sum_{\ell} w_\ell \log \pi_\theta(z_\ell \mid z_{<\ell})$$</u>

有了这个格式，混合就成了一件可以直接计算的事。

给每个数据源一个混合权重，所有来源的权重加起来等于 1，按概率抽一个来源，再从中抽一个样本，所有样本用同一个损失。

这里有一处容易算错。想让某个来源占 token 的某个比例，采样速率要正比于目标比例除以该来源每个样本的平均长度。<u>论文里的平均长度指语料或回答的平均 token 数，提示部分不计。</u>

预训练样本动辄几千 token，一条强化学习回答只有几百。~~假设~~<u>以示意的数字为例，</u>按条数一比四去混，token 占比就差了一个数量级，设计的配比和实际喂进去的配比会对不上。

生成和训练还可以各跑各的。

生成器把做好的一批回答写进缓冲区，训练器从缓冲区抽样更新，每隔若干步把新权重发给生成器。训练时用到的数据因此总比当前模型旧一点。

在传统的在线强化学习里，这是硬伤，过期的数据会让梯度估计出现偏差。这里的目标在构造时已经固定，旧数据仍然是一份~~合法的~~<u>明确的</u>似然目标，~~数学上站得住~~<u>可以照常拟合。论文也指出，同策略下成立的恒等式不能原样用在旧策略的数据上（附录 D.6）</u>。

它不保证这份旧目标对当前模型仍然最有用，所以~~滞后换来的是吞吐，付出的是学习效率，~~<u>滞后换来吞吐，代价论文没有单独测量，</u>究竟划不划算要靠实测。<u>论文抽查到的生成策略比最新训练步落后 12 到 44 次更新，训练实际用到的数据版本没有记录。异步实现的更新吞吐是同步实现的 7.8 倍，每次更新约 3.7 秒对 28.8 秒。但两套系统用的 GPU 数量不同，一套 24 块，一套 16 块，基线减法的写法也不同，这个差距没法归到某一个原因上。</u>

这张权重表装得下整个训练史。

分阶段训练是其中一条特殊的轨迹，每个阶段，某一个来源的权重是 100%，其余为零，阶段之间权重突然跳一下。

统一训练允许权重连续地变，也允许几个来源长期重叠。设计问题因此从每个阶段怎么配，变成了一条条权重曲线怎么画。

## ~~实验给出的账单，三项指标互相拉扯~~<u>实验给出的账单（上），任务表现与算力</u>

受控实验的舞台很小，一个 1.24 亿参数的模型，从零开始训练，预训练语料 200 亿 token，中训语料约五亿多 token。<u>强化学习阶段的结果是两个随机种子的平均，下文的“统一胜出”都应当放在这个规模里读。</u>

<u>还有一处细节。统一训练在预训练后段混入的中训序列，对全部 token 算损失，包括提示，分阶段中训则屏蔽提示（论文附录 C.2、C.3）。两组并不只差在数据配比上。</u>

任务是一种用自然语言出题的逻辑推理谜题，几个人住在不同楼层，线索给出他们的位置关系，要求推出完整分配。

谜题里有一类叫指代的短语，比如最高楼层的人，或者某人最好的朋友的最好的朋友。解开一个指代需要一个或几个操作。

设计的巧妙之处在于控制中训语料里出现哪些操作的组合。

中训里教过怎么找最高楼层的人，也教过怎么找某人最好的朋友，唯独没教过两者叠在一起，比如最高楼层那个人的朋友。强化学习阶段才引入这些新组合。

这样一来，模型没法靠背答案取巧，强化学习又确实有东西可学，测的是组合泛化。

评测分三档，难度逐级上升，题目规模在中训覆盖范围内的 Base，规模更大且强化学习里见过的 Extended，和比中训、强化学习都更大的 Extended generalization。指标有两个，pass@1（一次作答的通过率）衡量准确，pass@16（十六次尝试内至少对一次的比例）衡量覆盖。

先看任务本身。

最好的统一训练配置在 Base 和 Extended 上都超过分阶段训练，在没见过的大尺寸谜题上，优势依然成立。

预训练后段混入更多中训数据，效果更好，把中训语料复用两遍和四遍的配置表现最佳。强化学习阶段继续混入中训数据也有帮助，但不总是越多越好，最大的混合量下，Base 上的最佳准确率出现在中等的混入比例。

分阶段训练则有相反的现象，中训时间一旦超过最佳预算，最终准确率反而下滑。

再看一组数据。

强化学习开始之前，分阶段模型在 Base 上的准确率高于任何一个统一初始化，强化学习之后，最好的统一模型反超。

一种读法是，分阶段训练在中训阶段把演示过的模式学得更满，所以起点高。统一训练把同样的学习摊到预训练后段，表示保持得更宽，强化学习阶段有更大的空间去扩展。

这个机制没有被直接验证，只能当作一个有数据支持的推断。评价一份中训数据，只看它此刻让准确率涨了多少，不够。

换到真实语料上，模型是 0.76B 参数，数学题做强化学习，同时混入 2.4 亿 token 成分与中训相同的语料，里面有网页、数学、代码和推理轨迹。<u>这一部分的覆盖率用 pass@32 衡量，持续学习一节用 pass@16。</u>

把混入比例从 0 调到 5%，数学准确率几乎不动，数学覆盖率反而在最大的比例上最高。

留出语料损失在所有非零混合下都低于基座模型，比例越大越低，分阶段训练却让它升高。科学问答 SciQ 的准确率也跟着改善。<u>这里要注意，分阶段的 RL 基线是另一套同步实现。论文另设了零混合对照，用同一个异步训练器隔离混合本身的效应。零混合时留出损失同样上升，幅度是 0.074 nats/token，分阶段是 0.047。所以混入语料的改善要和零混合对照去比，与分阶段基线的差距里混着实现差异。</u>

代价出现在代码上，混入比例越大，代码准确率越低，尽管代码覆盖率仍高于基座和分阶段训练。对正在训练的数学任务，混入中训数据几乎没有成本，账单落在没有训练的代码任务上。

有人会想，加一项 KL 惩罚（KL penalty，约束模型别离基座太远）不也能保住通用能力。实验的回答是不能。

加大惩罚确实延缓留出损失变坏，同时把数学准确率和覆盖率一并拉低。试过的所有强度里，没有一个能同时拿到数学成绩、较低的语料损失和更高的 SciQ、MMLU 分数。

在强化学习阶段混入预训练文本，也有代价，留出损失下降，推理准确率和覆盖率在多数对比里降低。想保住通用能力，<u>在这个设定里，</u>调数据混合比加正则更直接，不过混合并不免费。

时机也是一个独立的量。

取平均混合比例都是 0.5% 的四种调度，恒定、线性衰减、线性增长，以及训练到一半就降到零，数学成绩基本一致。到一半就停的那种，最终代码准确率和 SciQ 更高，但留出损失的改善保留得更少。

早期混入和后期混入，起的作用不同，哪一种更好，取决于你更看重哪项指标。

![信息图7](images/info-7-fig8-schedules.png)

*▲ 论文图 8 重绘~~：~~<u>，</u>平均 0.5% 的四种混入时机调度*

接着是持续学习的实验，也就是开头那个结果。

先用分阶段方式和四种统一方式（恒定混入 0.5%、1%、2%、5%）训出数学模型，再让它们全部接上同一套不含中训数据的代码强化学习，跑 4000 次更新。后续阶段完全相同，变量只有前一阶段怎么训。

所有统一模型的起点代码准确率更低，终点在 HumanEval+ 和 MBPP+ 两个基准上的准确率更高，MBPP+ 的覆盖率也更高。混入 5% 的模型，四项指标全部最佳。<u>5% 是测试的最大比例，论文的说法是收益在最大比例处最强，并没有证明它是最优值。</u>

前一阶段怎么训，改变的是后一阶段能学到多高，这是分阶段流程里没法单独优化的量，因为中训阶段只留下一份检查点（checkpoint），没人能问这份检查点是不是最适合后续学习。

这个结论不止在这一条线上成立，论文在附录里换了一个通用推理域（WebInstruct）又复现了一遍。

最后是两个细节。

比较 MaxRL 和 REINFORCE，在恒定 2% 混合下，REINFORCE 的数学准确率、保留性更好，MaxRL 的数学覆盖率更高。

同一份中训语料里的成分也会影响代价，拿掉指定的代码来源，恒定混合下的代码准确率改善，换成退火调度几乎没有效果。比例、成分和时机三者互相牵连，只调其中一个，常常看不出规律。

## 配比轨迹，一种看训练的新方式

把前面的内容压缩一下，可以得到一个看训练的框架，叫它配比轨迹。<u>这个名字出自本文作者的归纳，论文里没有这个术语。</u>它由三部分组成。

第一部分是曲线。

每个数据源在整个训练中占多大权重，是一条随时间变化的曲线，阶段不再是独立的对象，只是权重在某个时刻跳一下。

曲线上有三个可以单独调的量，比例的高低，成分的构成，以及什么时候升什么时候降。这三个量在实验里~~各自独立地影响结果~~<u>各自都会改变结果，而且互相牵连，成分的影响会随调度而变</u>，所以不能靠一个数字概括配方。

第二部分是尺子。

判断一个训练决策好不好，用最终模型在真实任务上的表现来衡量，不用阶段内的指标。

分阶段训练选检查点，习惯挑中训指标最好的那个。这样挑出来的，未必对后续学习最有用，强化学习之前领先、之后落后的现象已经说明了这一点。

第三部分是取舍图。

把准确率、覆盖率和保留性画在同一张图上，扫一遍混入比例，固定基础设施。

这张图回答三件事，当前配置在哪里，往哪个方向挪会牺牲什么，存不存在各项都更好的位置。存在，就找到了值得押注的配方，不存在，至少知道了必须做取舍，不会被单一指标带偏。

怎么用，可以从成本最低的做法开始。

先改评测，保留各阶段的检查点，一起放到同一组下游任务上跑，按最终表现选。

再做混合实验，下次跑强化学习时混入 0.5% 到 5% 的前序数据，把 KL 惩罚组一起跑，对照着看保留性和主任务的变化，~~一个下午就够~~<u>工作量通常不大，这是作者的经验判断，论文没有给出耗时</u>。

然后把数据配比从写死在代码里的阶段，改成配置文件里的一张时间曲线，训练器读取每个来源在每个时刻的权重，损失不用动。之后试一试半程退火，改的只是一条曲线。

完整改造，也就是统一训练器、异步生成和加权似然损失，~~通常要按周计~~<u>耗时取决于现有代码，作者的经验是以周为单位，论文没有给出这类数字</u>，改造的主要工作量在数据管线、检查点逻辑和调度系统里的阶段假设。

这个思路也能借到训练之外的地方，当作类比。

一个人学新技能时，是把旧的练习完全停掉，还是留一小份，留多少，什么时候撤，同样是一条配比曲线，也同样有准确、广度和遗忘互相牵扯的账。

类比不带实验证据，它的作用只是提醒，凡是有顺序的学习，都可以问同一个问题，前一阶段怎么安排，会改变后一阶段能学到多高。

## 配方还没写完

这套思路把训练配方的调参，变成了一个有结构的设计问题，没有把答案直接给出来。

没有找到普遍最优的混合，算力分析只描述了评测过的配置，没有建立有预测力的规模定律。

5% 这个数字来自一个 0.76B 的模型、一份 2.4 亿 token 的语料和数学强化学习，<u>而且它是测试范围里的最大值，</u>换个任务，数字可能完全不同。

优化器也没有跟上数据的变化。

数据分布一路在变，强化学习阶段的学习率却固定在 1e-5，没有预热<u>（受控实验为 1e-5，真实数据实验为 1e-6，都是恒定值）</u>，是否该随数据配比一起调整，~~还没有人研究~~<u>论文留给了后续工作</u>。

实验大多一次只优化一个强化学习任务，真实训练几乎都是多任务，任务之间会抢学习信号，进度也不一样快。

阶段的概念也没有完全消失，把基础模型拿去适配一个具体任务，仍然需要一个单独的训练阶段，统一的是从零到通用能力这条主线。

于是留下一个开放的问题。

当数据配比成为一条可以设计的曲线，这条曲线由什么来决定？是按验证集上的取舍图手工画，是拟合出一套预测配比的规律，还是让训练过程自己调节，每一种答案都需要比 1.24 亿和 0.76B 大得多的实验去检验。

### <u>一份实现要对上的七件事</u>

<u>**一，样本是 (z, w)。** 每个 token 带一个权重，提示部分为 0，预训练和中训为 1，RL 的回答部分为奖励权重（`unified.py` 里的 `Example`）。多数训练栈已经有 loss mask，把它从 0/1 放宽成浮点权重就够了。</u>

<u>**二，一个损失，分母是批内非提示 token 的总数。** 对应 `weighted_loss`。有两处容易出错。权重为零的回答，它的 token 也要算进分母。分布式训练时，分母要在所有卡上汇总之后再除，否则每张卡各除各的，等于悄悄改了权重。后一点论文没有讨论，是我从实现角度做的推论，需要在自己的栈里验证。</u>

<u>**三，RL 的权重只有一行。** 对应 `rl_weights`。一道题采样 N 条，正确回答权重取 N/k（k 为答对条数，即 1/p̂），错误回答为 0，全错的题整体记零。换成 REINFORCE 只要把 N/k 改成 1。权重只由本组的通过率决定，不依赖另一个价值模型。这意味着现有的验证器和采样服务可以原样复用，只替换权重的计算。</u>

<u>**四，混合按 token 占比，速率正比于 f_s/T_s。** 对应 `MixtureSampler` 和 `draw_mixed_batch`。T_s 取损失 token 的平均数，不含提示。上线前像 `check.py` 那样抽样自检一遍，看实测占比与目标占比是否对得上。</u>

<u>**五，配比是一条曲线。** 对应 `pipeline.py` 和 `configs/`。每个数据源有一条随优化步变化的占比曲线，学习率也是一条曲线，同一份训练代码读取它们。</u>

<u>**六，生成与训练解耦。** 生成器用一份落后的权重副本，每隔几次更新同步一次，并记录策略滞后（`rl_phase` 与 `pipeline.py`）。论文的异步系统里实测滞后在 12 到 44 次更新之间。这里是单进程模拟，只能验证逻辑，吞吐上的收益要在自己的系统里测。</u>

<u>**七，用最终表现选检查点。** 保留每个阶段的检查点，放到同一套下游任务上评测，同时评测一份真正留出的前序语料。`task.py` 里有按哈希切分的做法，保证留出集从未进入训练。</u>

### <u>配比轨迹的两份配置</u>

<u>分阶段训练和统一训练用的是同一份训练代码，差别只在配置。横坐标相同的两个点表示跳变。</u>

<u>分阶段，占比只取 0 或 1，在阶段边界跳变。</u>

```

"mid": {"kind": "sft", "weight": [[0, 0], [200, 0], [200, 0.5], [400, 0.5], [400, 0.15], [550, 0.15], [550, 0]]}
```

### <u>搬进专业训练栈的顺序</u>

<u>下面按改动成本从低到高排列。前三步有论文的实验支持，后两步是我的建议，需要自己做对照。</u>

<u>**第一步，改评测与检查点选择。** 不需要重新训练。论文的持续学习实验说明，阶段内指标领先的检查点，不一定对后续学习最有用。</u>

<u>**第二步，在现有 RL 阶段混入 0.5% 到 5% 的前序数据。** 一定要设零混合对照，同时评测主任务、没有训练的任务和留出语料。论文这一组实验用的是 0.76B 模型和数学 RL，更大规模上是否成立没有证据。</u>

<u>**第三步，把阶段边界改成配置里的曲线。** 试一试半程退火。论文里混入的时机是一个独立的变量，调度不同，代码任务和留出损失的取舍也不同。</u>

<u>**第四步，把 RL 权重换成 MaxRL，并与现有做法对照。** 论文里 MaxRL 的覆盖率更高，REINFORCE 的准确率和保留性更好，两者在这份代码里一个开关就能切换。</u>

<u>**第五步，最后才动统一训练器和异步生成。** 这一步改动最大，主要工作量在数据管线、检查点逻辑和调度系统里的阶段假设。</u>

<u>每一步的对照协议都一样，同一个初始化、同一条数据流、同样的算力，多个种子。</u>

- RL 提示流共抽取 1488 道题，与评测题的重叠为 0。
- 策略滞后的均值，理论值 1.468，实测 1.468。
- 预训练阶段的训练损失，首段均值 11.7，末段分别降到 1.46 和 1.31。</u>

<u>RL(A) 训练通过率首尾对比只是观察项，不判定。首四分之一与末四分之一的均值，分阶段为 0.087 与 0.117，统一为 0.067 与 0.096，方向向上，但运行很短，不构成结论。</u>

<u>没有验证的内容也要说清。没有比较统一与分阶段的效果，也没有与论文数值对照。异步是单进程里用落后的权重副本模拟的，真实系统的吞吐和陈旧度没有验证。分布式下分母跨卡汇总没有验证。</u>

<u>`verify.py` 在单核 CPU 上约三分钟。`train.py` 是三种练法的并排对照，带零混合对照，耗时更长，不属于验证的内容。</u>

### <u>局限</u>

<u>模型只有 80 万参数。异步是单进程模拟。论文本身的证据也只到 1.24 亿和 0.76B 参数。所以这份实现能告诉你机制怎么写，但没法告诉你在专业模型上收益有多大，这需要按上面的顺序自己做对照。</u>
